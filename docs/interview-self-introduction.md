# AI 应用开发 / Agent 开发面试自我介绍

面试官您好，我叫李宗明，本科和硕士均毕业于华中科技大学。我的意向岗位是 AI 应用开发和 Agent 开发，其中，我最专注的技术方向是 RAG，也关注如何将检索能力与 Agent 的任务执行结合，构建能够解决实际问题的 AI 应用。

在华为实习期间，我参与了面向约束规划问题的 Agent 开发。这个场景的难点是模型需要正确选择求解器和 API，生成的模型还必须满足实际约束。我的任务是提升任务执行成功率，为此搭建了从问题解析、求解器路由到模型生成和执行验证的工作流，并结合 RAG 做能力检索，用约束和求解状态验证结果。同时，我使用 **Docker 部署 Sandbox**，为模型生成的代码提供隔离的执行环境，将执行结果用于验证和后续决策。在内部 500 条建模任务的 Benchmark 上，端到端成功率从 **68% 提升到 86%**。这段经历让我更加重视 Agent 的执行反馈与自动化评测。

我想重点介绍的项目是 **AITrans**，这是一个面向文献阅读、研究和知识管理的本地 AI Agent 工作平台。用户可以导入文档、围绕资料提问，让 Agent 检索证据、分析内容，并将结果沉淀为可复用的知识。项目的核心技术包括 RAG、LangGraph 和 ReAct，分别支撑知识检索、状态化任务编排和基于反馈的行动决策。

**第一是 RAG，这是我投入最多、也最希望深入的方向。** 针对文献中证据分散、局部片段缺少上下文的问题，我重点做了两项机制：一是结合文档章节结构的 **Small-to-Big 检索**，先定位相关片段，再在预算内补充同章节上下文；二是结合查询改写与多查询检索的 **证据门控机制**，根据证据数量、来源多样性和新增信息，控制是否继续检索。

这两项机制分别处理上下文完整性和检索停止条件，同时保留引用来源。评估时，我会分别检查检索质量和答案的证据支持程度，定位问题出在召回、上下文组织还是生成环节。

**第二是 Agent 的任务执行与编排。** 项目使用 LangGraph 管理执行状态，结合 ReAct 完成决策、工具执行和观察的循环。复杂任务由根图管理任务依赖、执行范围和预算，再协调专业 Agent 执行。我也关注 Dify 在 AI 应用和工作流搭建中的应用，并重视理解这类工具背后的上下文传递、工具调用和流程控制机制。

在工程实现上，我重视模型决策与程序控制的边界，并通过检查点、暂停恢复和执行追踪，让多步任务可观察、可恢复。

我对贵公司的相关研究和技术方向也有所了解，很认可团队在这一领域的探索。我希望把自己在 RAG 和 Agent 开发上的积累，应用到公司的实际业务中。我相信自己能够胜任岗位要求，也能够融入团队，与大家一起推动 AI 应用落地。谢谢。
