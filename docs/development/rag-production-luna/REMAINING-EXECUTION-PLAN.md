## 代码规范

1. 先定位入口、调用方、配置和影响范围；只改当前交付必需的文件/代码。
2. 复用现有 RAG、数据模型、存储、评测和 Debug Studio；不建平行系统，不改无关 Agent 模块。
3. 公共 API、默认行为和旧 JSON 保持兼容；需要新增合同先明确迁移及失败行为。
4. 保持现有命名、类型和异常处理；不做无关格式化、改名、移动目录或依赖升级。
5. 先复现具体缺陷，再做定向测试；后续只补调用链风险验证，最终才运行统一回归。
6. 测试失败先区分本次问题与历史问题；不删除测试、不跳校验、不硬编码成功、不吞异常。
7. scope、active generation、原文 span 贯穿各通道、context 和引用；失败必须显式可见，空范围不得变成全库。
8. 每批结束检查 diff；移除不必要调试代码，只提交当前 RAG 文件，保留其他工作区改动。
9. 模型、数据、配置、索引及产物指纹固定；真实测试、合成测试、未测试分开记录；未知成本写 null。

## 最终目标

- **功能闭环**：原文件导入 → 原子发布 → Dense/BM25/Graph 召回 → 融合/重排 → 原文证据 → 有依据的答案；重建、删除、重启和失败回退正确。
- **安全硬门**：越权结果/图路径、过期或不存在的引用、半成品索引可见、未处理崩溃、已修坏例复发均为 0。
- **证据闭环**：每条引用绑定 scope/generation/source span；相关但不足、无相关证据、检索失败分开；知识专属问题无证据时不得冒充文献结论。
- **评测闭环**：文档/证据检索指标、完整证据集覆盖、独立 claim/citation 评测、拒答、延迟和成本可重放、可分层；不用被测系统自报 supported 当真值。
- **运维闭环**：单请求全链路 trace、坏例分类/回放、CI 阻断、冷暖/并发/故障负载、版本缓存、回滚方案。
- **发布结论**：冻结配置完成 S16 矩阵和最终复核；只有质量/安全/延迟/预算及人工检查全部通过才推广默认 Graph/Router/更大重排池。否则给出准确 NO-GO 与失败项，不能用代码完成替代生产验收。
