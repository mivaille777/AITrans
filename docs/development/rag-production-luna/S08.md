## 配置与预算

应用设置的 `rag` 对象支持：

```json
{"query_rewrite_enabled": true, "query_router_enabled": false}
```

现有改写默认 true 保留；新通道路由默认 false，没有将未证明有收益的规则默认打开。构造 `CompanionChatService` 可传对应 `rag_rewrite_enabled` / `rag_router_enabled` 参数做隔离验证。应用单例重新构造时读取设置；未增加 UI 控件或修改用户当前设置。

| 题型 | 路由启用时的通道 | 查询/尝试预算 |
|---|---|---|
| keyword | BM25；不调用改写模型、不主动启用图 | 1 个原始查询；通道全失败时最多再用现有默认通道尝试原文一次，总尝试≤2。 |
| semantic | 现有 Dense + BM25 | 原文及扩展合计最多 3 轮。 |
| multi-hop | Dense + BM25；图由已有运行时开关决定 | 最多 3 轮；不替 S06/S07 启用图库。 |
| no-answer | 无 | 仅对空 query 或可信空 scope 判定，0 轮；不根据一句问题预测语料一定无答案。 |

路由关闭时不传新的通道参数，保持现有 Dense/BM25/Graph 配置。原始 query 先检索，再使用剩余预算扩展；即使结构意图存在，也不能替换原文。Model 不接收/返回可执行的文档范围；策略 proposal 不能授予全库访问。每次检索复制 filters，避免组件修改它影响下一轮。

计划使用旧字段兼容的 Pydantic 字段，在校验时重新派生规范化文本、改写列表和题型，保留 extra=forbid。调用方检测到模型序列化往返失败后，已修复字段表示，没有放宽额外字段校验。语义型判断是有界字面规则，属于待评估的工程策略，不能代表生产意图识别准确率。

复用现有 AI 客户端 timeout/retry；TimeoutError/AI 错误及其他规划错误回退原文并保留诊断。本轮没有增加能强制中断同步调用的自定义硬超时，不能承诺新的墙钟 SLO。改写模型只请求搜索计划，不运行回答生成。
