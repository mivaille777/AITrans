# 检索效果、并发与独立引用：本轮实施与验收

日期：2026-10-03。分支 `electronrebuild`，基准 HEAD `4b0d802c`；保留进入本轮时已有工作区修改，未提交/推送。仍按 Recall@5≥0.80、MRR≥0.70、独立引用准确率≥0.90、暖完整检索 P95≤800ms 验收。

## 本轮必要修改

| 文件 | 必须修改的原因 |
| --- | --- |
| `backend/rag/sparse/store.py` | 大库每次对约八万条命中做 Python 元数据检查。改为分数堆取出最佳项、通过原有权限/代际/参考文献过滤后才返回，凑满 top_k 即停止；小范围查询限制堆扫描次数，复用原筛选路径回退，评分、排序规则和接口不变。 |
| `backend/rag/inference_worker.py` | 普通 Lock 不保证等待请求顺序，连续新请求可能抢占旧请求。增加 FIFO 等待顺序，保留原有超时、取消、杀进程与恢复行为；记录线程独立的排队/执行/总耗时。 |
| `backend/rag/retrieval_service.py` | 将 worker 排队与执行耗时附入现有 embedding/rerank Trace，区分模型速度与等待。缓存命中不附入旧推理耗时。 |
| `scripts/calibrate_rag_judge.py` | 明确否定、数值和关系方向校验；复用已有裁判工具，增加固定种子、样本数、历史题排除及 MS MARCO 参考资料接线，保留默认 Dolly 调用与原始人工标签。 |
| `tests/rag/test_bm25.py` | 覆盖高分越权/旧代际/参考文献候选在前时继续寻找合法结果，以及同分稳定排序与空允许范围。 |
| `tests/rag/test_inference_worker.py` | 验证 FIFO 顺序、取消等待者清理、线程耗时隔离；原有超时杀进程和恢复测试继续通过。 |
| `tests/rag/test_rag_judge_calibration.py` | 验证新数据源按问题划分、排除历史题、参考资料绑定与上游标签保真。 |
| 本文、`OPEN-ISSUES.md`、`STATUS.md` | 保存真实结果、撤回的实验、验收边界与后续决策，更新最新状态。 |

未新增依赖、模型或生产开关；未修改公共 API、生产融合权重、重排候选数、用户索引或引用守卫阈值。

## 验证与结果

### 1. 大库检索与并发

MedicalRetrieval 全部100999篇，固定 dev100/seed42；现有 Qdrant 服务端、真实 spawn Embedding/Reranker、缓存关闭。800次完整检索（700次保留重排、100次扩大召回诊断）全部零错误、结束后模型子进程零残留。700次生产配置输出的100题逐题排序一致。

先用同一个 BM25 实例对原实现和候选方案配对：100题分数/排序完全一致，C1 P95 **142.94→41.09ms**；C4 单阶段 P95 **1257.27→515.92ms**。这是孤立 BM25 实验，不能当成完整请求容量。

| 本轮完整链路 | C1 P95 | C4 P95 | C4 P99 | C4 QPS |
| --- | ---: | ---: | ---: | ---: |
| 修改前 | 911ms | 2403ms | 3552ms | 3.18 |
| 仅候选筛选优化 | 675ms | 2932ms | 4271ms | 2.95 |
| 最终筛选优化＋FIFO | **717ms** | **1778ms** | **1877ms** | 2.89 |

最终 C2 的 P95=1047ms，仍失败。FIFO 降低尾部等待，没有提升模型吞吐；最终 C4 重排平均排队746ms、执行337ms。模型执行计时包含该子进程内的方法处理，冷调用包含模型加载；IPC与父进程处理保留在总时间，延迟未扣除排队。

最后针对小范围查询补充保护：指定少量文档时先用现有文档允许范围筛选，其他选择性条件限制扫描后复用原堆筛选。最终100道全库、20道单文档配对分数/排名完全一致；平均耗时分别153→47ms、56→44ms。撤回的扫描方案和中间结果也保留，未只留下较好报告。

共享本机系统内存峰值约15.79GiB，RAG进程树峰值约7.53GiB。Docker恢复后原有容器也继续运行，未停止其他应用。各完整跑次存在系统负载和 Qdrant 缓存影响，不把一次P95下降全部归因于代码，也不以拒绝并发请求冒充容量通过。此前1465ms的C4报告仍保留；本轮不声称超过那次环境表现。

最终 Medical Recall@5=**0.63**、MRR@20=**0.5278**，效果门失败。

### 2. 召回实验

- 对固定开发题离线检查等权与稀疏权重0/0.25/0.5/1/2，以及8–60候选；没有发现可推广的融合权重收益，未新增生产权重配置。
- 原 Dense30/BM25 30候选并集覆盖率0.72；扩大到两路各100后 Dense覆盖0.76、并集0.78，仍低于0.80，且等权RRF前20覆盖反降至0.64。没有将扩大参数推广到生产。
- 因此仅调整重排无法解决全部遗漏。22条扩大召回后仍漏掉金标的题已可从冻结逐题结果复现；部分金标为通用医学回答，而高位候选更贴近问题。不得按该观察改金标或把替代答案计成命中，须独立复核。
- 未用QASPER181 holdout调参；未对已见SciFact test反复选择参数。

## 未解决风险与下一步决策

1. **检索效果FAIL**：扩大召回和融合权重均不足。先人工复核22条开发坏例和金标歧义，再决定是否评估新文本Embedding；改变模型/指纹必须独立重建索引和回归，不能复用旧向量冒充兼容。
2. **并发FAIL**：C2/C4仍超过800ms；尾等待已改善，吞吐未提升。本机持续接近内存上限。后续可选择独立模型推理进程的跨请求微批处理或增加内存/独立推理服务；这涉及队列、取消、超时语义和运行资源，不能作为本轮几个参数的安全替换。
3. **独立引用BLOCKED**：自动裁判仅0.70支持精度。先完成材料双人盲评与争议裁决；不得降低门槛、删除拒答或用内部guard代替人工准确率。
4. **Graph多跳效果FAIL**：完成构图后仍只有0.20完整证据集覆盖。须选与实际资料相符的关系类别，逐类建立肯定/否定/反向/多主体测试和独立关系标注，再扩展白名单；不让通用百科关系无条件进入科学图谱。

当前结论：功能修复与公开构图复验完成，**效果/并发/独立引用验收整体 NO-GO**。
