## 已核实的调用链

### 文档导入与索引

POST /api/knowledge/documents → backend/api/knowledge.py:99 的 import_knowledge_document → KnowledgeLibraryService.import_document（backend/services/knowledge_library_service.py:126）→ IndexService.index_document → parser → chunker → embedding → Qdrant upsert → BM25 文档删除并重建 → 删除旧向量 chunk → manifest READY/upsert。

源码位置：

- API 与文库服务调用：backend/api/knowledge.py:99、backend/services/knowledge_library_service.py:126。
- runtime 装配：backend/api/knowledge_dependencies.py；分别创建 QdrantLocalVectorStore、BM25SparseRetriever（bm25_index.json）、IndexManifest（index_manifest.json）、RetrievalService、IndexService 和 KnowledgeLibraryService。get_rag_runtime 使用 singleton。
- 实际写入次序：backend/rag/index_service.py:204–247。向量、BM25、旧向量清理和 manifest 是多个步骤；异常会把 manifest 标成 FAILED，但可能已发生的外部写入不在同一事务中。这印证了 S01 的一致性任务。
- parser/config 读取点：config/default.toml:80–87；Docling 开启，OCR 与 formula 默认关闭。

### 在线检索与调用方

主检索在 backend/rag/retrieval_service.py:33：Dense embedding/vector search、BM25 search、可选 section search → RRF fusion → reranker → final candidates → small-to-big；metadata 含各通道候选数、前后 rank IDs、耗时和 fallback。

配置在 config/default.toml:164–201：Qwen3 Embedding 0.6B、1024 维；Qdrant Local；Dense/Sparse Top30、Fusion Top20、Final Top8；Qwen3 Reranker 0.6B。config/default.toml 未设置 rerank_candidate_k；backend/rag/config.py:261 将 effective_rerank_candidate_k 回退到 final_top_k，所以普通请求默认只重排前 8 个融合候选。

两个主要调用方：

- Companion：backend/services/companion_chat_service.py:305 的 prepare_knowledge → 规范化可选 document IDs → query_planner.plan → build_structural_queries → 对每条 query 调用 retrieval_service.retrieve → merge_query_results。若所有检索都失败，会返回“Knowledge retrieval was unavailable”，并允许一般回答但不引用来源。
- Agent：backend/agent_tools/knowledge.py:319 的 search_knowledge_base → 从 invocation context 解析允许的 document IDs；既无显式范围又不允许 global 时抛 PermissionError → Query Planner → RetrievalService → scope 校验 → evidence/citation。此处范围合同比 Companion 强，后续 Graph channel 必须遵守同一范围。

### Graph、评测和调试边界

- Knowledge Canvas 路由是 /knowledge/canvas：backend/api/knowledge_canvas.py。它使用 backend/services/knowledge_graph_repository.py 的 knowledge_canvas_graph SQLite 单行 JSON payload；空图读取时会填 demo nodes/edges。/retrieve 调用 AgentKnowledgeRetriever。
- backend/services/agent_knowledge_retrieval.py 用 query token overlap 找节点，再用 relation degree 加分；其注释说明向量结果是 future capability。该路径返回 Canvas 节点证据，不返回 RAG DocumentChunk，也不进入 backend/rag/retrieval_service.py。
- 因此已有两类“图”相关代码，但都不是论文 RAG 的 Graph Retrieval：Canvas 是独立图视图/检索，AgentKnowledgeRetriever 是卡片图召回。
- Debug API 在 backend/api/rag_debug.py，前缀 /api/rag/debug；包含 runs/events、datasets、evaluation、compare、QASPER run/case API。前端 trace 组件是 apps/desktop/src/features/settings/RagDebugStudioTrace.tsx。
- backend/services/rag_debug_service.py:413–414 当前给 ranked_chunk_ids 与 pre_rerank_chunk_ids 写入同一 ranked 列表；当前数据集评测不能据此比较 rerank 前后顺序，S09.1 应先修该记录链路。
- backend/rag/benchmarks/qasper/README.md 明确每题用自身 paper 的 document_id filter；adapter 从结构化 QASPER 记录构造文档/段落，不走真实 PDF parser。它适合已知论文条件下检索评测，不能单独代表开放式文档发现与 ingestion。
