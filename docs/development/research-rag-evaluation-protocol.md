# 科研 RAG 分组件与端到端评估协议

状态：设计与验收协议，尚未实现。配套任务书：[research-rag-refactor-taskbook.md](research-rag-refactor-taskbook.md)。

## 1. 评估要回答的三个问题

1. **组件是否做对自己的事？** 例如 RAPTOR 是否找回跨章节原文，HippoRAG 是否召回全部多跳支持，RCS 是否保留关键证据。
2. **它是否改善最终回答？** 在同一问题、语料、模型和预算下，加入该组件后，答案正确性、完整性、引用支持及拒答是否改善。
3. **收益是否值得代价？** 同时记录索引构建、查询延迟、token、模型调用、存储和失败回退；不能以无限扩大候选集换取 Recall。

分别报告**局部效果**（冻结上下游，只替换被评组件）、**实际系统效果**（从导入到最终回答全链路运行）和**交互效果**（两个组件组合是否互补）。完整系统分数不能直接归因于最后加入的模块。

## 2. 数据集和标注

### 2.1 三套材料，三种用途

| 材料 | 用途 | 能作出的结论 |
| --- | --- | --- |
| 可入仓的小型合成论文语料及假模型 | CI、错误注入、权限/版本/回退、每个算法的确定性边界测试 | 功能正确、契约稳定；不声称真实效果提升 |
| 本机真实论文开发集（先用四篇论文和 12 道烟测，再扩充） | 调 prompt、预算、阈值及发现失败模式 | 探索性结论；不得用作最终上线增益证明 |
| 冻结的独立真实论文验收集 | 预先登记的消融、人工盲评、成本报告 | 在该语料和任务分布内的效果结论 |

原任务书的“60+ 道独立题”作为**先导评估起点**，不足以自动支持所有细分问题类型及多个消融结论。先由产品目标预设最小有意义提升，先导集估计方差与基线正确率，再确定正式验收样本量；每个目标类型都报告题数和置信区间。若区间太宽，标记“证据不足”并补题，不以未显著的结果宣称无效。四篇方法论文可用于开发烟测，不能单独支撑引用图、长文档或大规模实体图的效果结论。

按**文档/论文家族**而非只按问题拆分调参与验收，避免同一段落或同一组引文关系同时出现在两边。验收题由目标科研任务构造，覆盖事实定位、长文档主题、多跳、跨论文综合、矛盾证据、范围限制和语料内无答案；中英文分别计数。生成式问题可用于扩充候选，但正式题目、答案与 gold 证据须人工核验。

### 2.2 一题的 gold 契约

每题记录 `case_id`、允许的 workspace/文档版本、问题类型、预期可答/应拒答、答案要点（facets）、正确与常见错误答案、相关论文、原文证据位置、可接受引用范围和权重。每个要点的证据采用 **OR-of-AND**：同一事实可能有多组替代支持集合，每组内可要求多个原文片段同时出现。这样既能评价多跳的“全部必要证据”，也不会因另一组同样正确的论文/段落被误判为失败。原文位置由文档 hash、页/章节和字符区间锚定，`chunk_id` 只作当前索引映射。

“语料内无答案”“被范围限制排除”“证据冲突尚不能定论”分开标注。无答案题也可以含**相关但不足以作答**的原文，不能强制 `relevant_chunk_ids=[]`；现有 `RagEvaluationCase` 校验规则需要为新协议扩展，并与旧数据兼容。每题至少两名标注者独立判定答案要点、关键原文与可答性，分歧仲裁并保留记录；对新增图边、RCS 摘要及引用支持用抽样双标和一致率审计。最终人工评分隐藏系统名称与配置。

## 3. 指标分层：从原文到答案

| 层 | 主指标 | 诊断指标与失败解释 |
| --- | --- | --- |
| 解析/索引 | gold 原文可定位率、页/区间正确率、当前版本一致率 | 表格/公式/参考文献解析失误；重建/删除后悬空 ID；建索引时间/存储 |
| 论文候选 | Gold-paper Recall@k、论文级 nDCG、引用扩展新增相关论文率 | 初检漏论文、扩展噪声、范围越界；有 DOI 与无 DOI 分开报告 |
| 原文候选 | Recall@k、nDCG@k、All-support@k、**按相同 token 预算的 All-support** | 每题是否至少有一组完整支持集合进入上下文；无关证据比例与排序损失 |
| 证据筛选 | 关键原文保留率、无关片段剔除率、摘要事实支持率、选后 All-support | RCS 是否删掉唯一关键证据；摘要是否引入原文没有的事实；上下文压缩率 |
| 答案 | 要点正确率/覆盖率、已回答问题精确率、全题正确率、拒答率与拒答正确率 | 事实错误、遗漏、过度推断、冲突处理；同时给出回答率—错误率曲线，避免靠大量拒答刷高精确率 |
| 引用 | 可打开率、claim—原文**语义支持** precision/recall/F1、无引用事实率 | 区分“引用 ID 合法”“原文包含关键词”“原文真正支持该句”；检查多句共用引用与错配 |
| 运行 | p50/p95 延迟、每题 token/调用/成本、失败/回退率、构建成本和更新成本 | 索引费用按预先登记的查询量摊销，同时单列冷启动与热查询 |

检索无结果不等于正确拒答；检索到若干无关结果也可能需要拒答。因此现有 `backend/rag/evaluation.py` 的 `no_answer_accuracy` 只用作**检索层旧指标**，生成层另以真实最终回答打分。现有 `RagEvaluationPrediction.claims[].supported` 由预测记录提供，不能自行充当人工真值；正式引用指标必须先把**模型实际生成的答案**拆成原子事实句，再由独立标注者核对其引用的原文。自动 judge 可负责初筛，但须在人工盲评子集上校准，并报告错误及不确定性。评估 judge 与被评系统不得共享可污染判断的答案提示。

## 4. 各组件的独立实验

| 组件 | 固定条件与对照 | 该组件的主效应 | 特有质量/成本检查 |
| --- | --- | --- | --- |
| SciRAG 外循环 | 同一检索器与生成器；固定单次查询/现有规划器/提纲+初稿+批判树；再分解无提纲、无批判、仅顺序、仅并行 | 要点覆盖、批判后补到的有效证据、最终正确率/引用 F1 | 无效新查询率、每层深度收益、节点/时间/token、回写造成的引用丢失 |
| SciRAG 节点内算法 | 同一树；dense/现有 rerank 对照引文扩展、角色/贡献链、符号重排的逐项关闭 | 新增相关论文、同 token 预算完整证据进入率、答案质量 | 引文错边、关系错判、保留反证、扩展噪声及耗时 |
| PaperQA2 工具策略 | 同一搜索/Gather/Answer 工具；固定 Search→Gather→Answer 与 Agent 自选动作 | 重搜/引文后 Gold-paper Recall、最终正确率与拒答质量 | Search→初排→RCS→引用的逐层流失、动作数及无增量循环 |
| PaperQA2 RCS | 冻结候选及下游生成器；原文直入 / RCS，另比较模型与候选深度 | 关键证据保留率、答案精确率、Claim 支持 | 错删关键片段、摘要失真、额外 token/延迟；弱模型可造成负收益 |
| RAPTOR | 同一叶子、嵌入和生成器；叶子检索 / 相邻章节摘要 / 语义软聚类树；collapsed tree / 逐层遍历 | 长文档主题和跨段题的完整原文支持召回、答案要点覆盖 | 摘要→叶子回收损失、细节事实退化、摘要失实、构树/重建成本 |
| HippoRAG | 同一叶子及后续重排；纯 dense/BM25 / 仅种子 / 一跳 / 完整 PPR，再分别关闭同义边与特异性 | 多跳 All-support@k、最终多跳答对率 | 实体对齐、OpenIE 边正确率、同义误连、段落回投、泛化实体误检、离线/在线成本 |

上述是**组件内消融**。要测实际增益，还必须让每个变体从用户入口完整运行，包含索引失败、模型超时和回退；分别报告“尝试开启该组件的全部问题”与“组件实际成功参与的问题”。只展示成功参与的题会高估效果。

## 5. 全系统实验矩阵与归因

先在固定的基础流水线 `B` 上比较 `B`、`B + SciRAG`、`B + PaperQA2 工具策略`。两种外层控制器互斥。随后在 **同一个控制器和同一批问题** 下依次测 `+RCS`、`+RAPTOR`、`+HippoRAG` 及 `+RAPTOR+HippoRAG`。对完整系统再做 leave-one-out（分别关闭 RCS、RAPTOR、HippoRAG、SciRAG 内层功能），避免把后加组件的收益与已有组件的交互混为一谈。若某一对组件在目标问题上都有明显作用，再做二因素四格实验 `{都关、仅 A、仅 B、都开}`；交互效应为 `Q(AB)-Q(A)-Q(B)+Q(无)`。路由/控制器本身也要与固定人工路由比较。

每个比较保存**相同 case_id 的逐题结果**。在“同一候选数/上下文 token/查询延迟或 LLM 预算”的受控条件下估计质量提升；另给出各系统真实资源消耗下的质量—成本曲线，避免把“多花资源”误解释为算法改进。预先指定每个组件的主指标与目标题型，其余为探索指标；例如 RAPTOR 的主结论来自长文档主题题，HippoRAG 来自多跳题，而不是被大量简单事实题稀释的总平均。

为定位损失，可做三种**诊断性 oracle 干预**：给定 gold 论文集合后测片段检索、给定 gold 原文集合后测证据筛选/生成、给定 gold 证据且不运行检索后测最终答案与引用。Oracle 只诊断上限和瓶颈，不进入正式系统成绩。报告每层 gold 保留率的下降位置，避免检索失败被误判成生成失败。

## 6. 统计与人工评审

先导集只用于设计实验。正式验收前登记：语料及题型、目标指标、最低有意义提升、最大可接受成本/伤害、候选配置和停止规则。使用同题配对差值；问题在同一论文下相关，置信区间应按**文档/论文家族成簇重采样**而非把所有题视作独立。报告点估计、95% 区间、题数及逐题胜/负/平；二元正确率可附配对检验，多项预定主比较控制多重检验。含随机性的生成实验在相同配置下重复运行并报告波动。区间跨越预定最小收益时记为“未证实”，不据此推断没有效果。

人工评审采用原子事实句的“支持/不支持/冲突/无法判断”标签，并独立评分答案正确、覆盖、相关性与组织性；评审者可查看原文，但看不到实验组。对引用与摘要定期复核自动 judge 的假阳性、假阴性。总分不得替代失败案例：每次报告按题型列出完整支持未召回、摘要失实、实体误连、引用错配、无证回答及错误拒答的具体例子。

## 7. 发布判定与交付物

一项组件只有同时满足以下条件才默认开启：目标题型主指标的**配对提升及其 95% 区间**达到预先登记的质量门槛；引用语义支持与拒答的退化上界不超过已登记的容忍值；范围越界和失效引用的观测数为零；成本/延迟在登记预算内。质量门槛应同时考虑最小有意义提升，不能只看点估计或 `p < 0.05`。若证据不足则继续保持可关闭的实验分支。对索引失败、图无种子、RCS 超时等回退分别展示发生率和全链路影响。

每个评估版本保存 `dataset.jsonl`、`corpus_manifest.json`、`run_config.json`、逐题 `prediction.jsonl`、分阶段 Trace、自动与人工标注、成对比较报告、失败案例和复现命令。复用现有 `backend/rag/evaluation_dataset.py`、`backend/rag/evaluation.py`、`scripts/evaluate_rag.py` 与 RAG Debug Studio；增量扩展真实答案/证据标签和逐阶段预测，而不是重建一个平行评测系统。无 GPU CI 跑确定性小语料；真实模型与人工标注的效果实验单列为版本化、可复现的评估作业。

评估框架参考：四篇本机论文的原始消融；[ARES](https://aclanthology.org/2024.naacl-long.20/) 对检索上下文相关性、答案忠实性与答案相关性的分层评估及人工校准；[RAGBench](https://arxiv.org/abs/2407.11005) 的可解释标注思路。上述文献不替代本项目独立人工 gold 和配对消融。
