# 工具参数异常恢复与全文读取（2026-10-06）

用户批准方案后实施。历史截图对应会话中，助手消息为 provider/error，正文为空。旧代码在一次修复后再次收到坏参数即抛出异常；现有日志没有保留具体错误字段，因此不能断言历史失败是哪个参数导致。

## 修改理由与验证依据

| 修改 | 具体理由（高置信度） | 验证 |
| --- | --- | --- |
| 校验与执行分离 | 原来的大 try 同时包含 JSON、Pydantic 校验、重复检查和服务执行，服务 ValueError 会被误认为模型参数错误 | 注入服务 ValueError 后报告 tool_unavailable，不进入参数修复 |
| 严格字段反馈、安全默认值 | 泛泛“遵守 schema”无法指出错误；代码围栏和缺省 top_k 不需要猜测语义，ID/类型转换则会改变权限或请求含义 | JSON 围栏、继承服务端范围、默认 top_k=5；布尔值、越界值、未知字段和缺失 query 保持拒绝 |
| 按响应批次计修复，最多两轮 | 同一批包含多个坏调用时，逐个扣“修复次数”会在模型尚未收到反馈前终止；原来无效调用还会消耗实际调用预算 | 同批两个错误均收到对应 tool_call_id 的错误响应，只计一轮；第三轮或相同错误指纹进入兜底 |
| 实际预算与重复缓存 | 参数未通过校验没有执行副作用；同批调用也必须逐个检查剩余预算 | 无效调用不扣 Search/Read；同批第三次 Search 不执行；成功重复 Read 复用结果 |
| 服务端只读兜底 | 已定位或已读取证据可继续利用，模型参数故障无需变成空消息 | 使用原始用户问题和已确认范围；读取已定位证据；最终生成失败时只保留带引用的原文摘录 |
| 独立全文路线 | 旧路线最多 4 次片段/邻居读取，无法证明全文完成。本地 36 页文档还存在 21,203 字符的大块 | 发布清单精确枚举、按 chunk_index 排序；长块连续拆分；逐批传入模型，统计片段、字符、批次 |
| 版本与引用边界 | 枚举后或最终生成期间可能重新发布文档，旧证据不能冒充当前版本 | 原有 active-generation/source-span 校验继续生效；汇总前、回答释放前再次验证固定版本；版本改变时撤销证据和引用 |
| UI 与历史回放 | 旧失败消息持久化正文为空，因此重开会话仍显示 No response content | 恢复/全文进度事件；partial/blocked/fallback 区分；非空错误正文；恢复与覆盖元数据保存并通过会话 API 回放 |

NEVER 不访问资料。未明确全文目标且库中存在多份文档时，要求选择文档。全文追问仅承接用户历史问题，不把助手历史回答当证据。普通对话遇到不可解析的模型响应、且没有资料调用或已确认文档范围时，不触发全库读取。

## 预算与完成含义

普通路线：最多 10 次决策、2 次 Search、4 次 Read、7 次实际工具执行。修复最多两轮，相同错误指纹提前结束修复。成功重复调用不重复执行。

全文路线：最多 24 个正文处理批次、30 次服务器只读操作。每批正文最多 12,000 字符，长块按连续区间拆分并保留原始引用；批次笔记总量最多 48,000 字符。两条路线共享 240 秒总时限和取消信号，单工具/模型操作最多 120 秒。全文不完整时返回可核验证据与进度，不释放自称已读完的模型回答。

“完整”仅指当前发布索引内的全部可用正文，要求所有片段、字符和批次都已处理，并通过版本复核。界面正文明确说明图片、扫描页和未解析内容不在完成标记内。覆盖统计证明文本已传入模型，不证明模型理解了每个事实；最终回答仍通过现有引用/证据一致性校验。

取消会阻止后续操作及结果释放。底层阻塞 SDK 调用可能直到其超时才退出，后台只读线程不获准提交迟到的结果。总时限耗尽后只允许释放已取得的内存证据，不继续发起模型/资料调用。
