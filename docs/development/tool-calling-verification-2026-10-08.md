# 工具调用与任务验收改造

本次按用户确认实施：工具是否合法、结果是否真实、任务是否完成分别检查；保留现有界面组件样式和 LangGraph / ReAct 运行时。提交还包含本轮所依赖的先前 Chat 布局、输入栏、文件导入、工作区、计划审批与 Markdown 导出改动。启动顺序及其他 RAG 实验改动不在本次提交范围。

## 用户可见行为

- 自动工具选择先按本次用户消息识别能力，再与会话选择、服务可用性和后端权限取交集。未知表述交给现有语义决策；附件中的文字不获得指令权限。
- 工具管理、Chat 工具目录及模型参数来自注册表。参数保留完整 schema、必填项及类型约束；修改工具标题或默认值不能暴露服务端上下文字段。
- Plan–Execute 显示计划及服务端确定的验收条件，仍必须由用户确认后执行。结果失败或无法核对时停止后续计划步骤。
- 模型收到实际执行状态和验证报告。进程退出异常、写入无法回查、未执行必要步骤、缺少文档证据或全文读取缺页不能标记为全部完成。
- 右侧分别显示运行生命周期、任务验收和每次工具调用的参数、权限、结果、验证、耗时及重试。历史事件缺少验收证据时显示尚无记录。
- Markdown 显示正文生成与下载触发；不把浏览器开始下载当作已保存到用户磁盘。必要目标未通过验收时抑制自动导出，避免输出虚假的完成报告。

## 服务端边界

- 统一结果增加 status、tool_call_id、duration_ms、attempt、verification 和 error_code。
- 进程检查退出码、超时及资源限制；文件在授权工作区回读；知识片段回读、范围及引用校验；笔记和知识卡核对持久化内容及来源关系；Markdown 核对正文、文件名、编码和摘要。
- 验证只执行读取，受运行预算及最多 10 秒等待限制。写入完成后验证失败保留物理回执，不重试实际写入；缓存回执再次核对效果。
- 物理执行回执和任务完成状态分开持久化。失败、取消和未知执行结果也产生任务验收事件。遥测保留验证状态及计数，继续剔除原文、模型正文和详细证据。
- 保留现有研究任务 required 标记和验收要求，保留现有引用/证据核验。默认 ReAct 仍每轮决策一个工具；既有安全并发规则保持。

## 验证范围与限制

- 覆盖假成功退出码、错误写入回执、未知写入不重放、验证超时、跨范围结果、缺失步骤、全文分页缺口、研究必要步骤失败、模型跳过执行、真实失败状态回传模型、失败计划停止依赖步骤及遥测脱敏。
- 前端相关 19 个测试文件共 88 项通过；生产构建及类型检查通过。
- 从 Git 暂存内容导出的独立目录验证后端 Agent、工具 API、工具测试、会话导入、原生调用、研究与多任务流程及崩溃恢复：1051 项通过，没有跳过。随后新增两项真实失败进程验收用例，三项 Agent Docker 用例通过。
- Docker Desktop 已安装，初次检查时引擎未启动；启动后使用现有 aitrans-python-sandbox:v1 镜像。Python、命令与安全基线的 29 项实机测试全部通过；加上新增两项非零退出码验收，共 31 个不同的 Docker 用例。覆盖网络隔离、非 root、Docker socket 隔离、输入只读、工作区变更、超时、OOM、输出限制、结果验证及容器清理。真实执行失败时，即使测试模型宣称成功，任务验收仍不通过，自动 Markdown 导出被阻止。
- 独立目录前端 88 项测试、测试类型检查、Electron 编译、Vite 构建和 PDF 离线资源检查通过。复用 node_modules 的 Windows junction 会改变 Vite manifest 模块路径；独立验证仅增加 preserveSymlinks 配置以保持模块位置，不改生产配置。定向 lint 无错误，现有 inspector 辅助函数导出有两个 Fast Refresh 提示。
- 验证报告的 semantic_quality 为 not_assessed。结构正确、退出码为 0 和持久化成功不能单独证明所有自然语言目标或生成内容质量；未建立专门语义验收的工具不会伪造质量保证。
- ReAct 中失败的调用保留为未通过项，不由后续任意一次同名工具成功静默覆盖。需要用户继续处理时结果如实呈现部分完成或待核对。

前端开发服务可加载新界面；后端 Python 和 Electron 进程需要退出后重新通过 start.ps1 启动，才能加载最终实现。
