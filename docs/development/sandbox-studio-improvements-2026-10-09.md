# Sandbox 隔离与 Debug Studio 完善

本次改动保留原有权限、网络审批和工作区回写审批，补充运行可观测性、容量约束、异常回收和产物操作。

## 已实现

| 能力 | 行为 |
| --- | --- |
| 实时日志 | Docker attach 输出以累计快照更新 stdout / stderr，限频发布；已知密钥和宿主路径脱敏，跨帧密钥前缀暂缓显示。 |
| 断线恢复 | WebSocket 每次连接先返回当前快照，单调序号防止旧事件覆盖新状态；前端退避重连并读取原任务，不再次提交执行。 |
| 历史任务订阅 | 从 Runs 选中仍在运行的任务后继续订阅。取消显示 cancelling，收到终态和清理结果后才结束。Agent 任务由其运行控制器取消。 |
| 资源采样 | 从 Docker stats 读取 CPU、内存、PID；缺失值显示未知。显示工作区、输出和日志容量；短任务也记录最终日志字节数。 |
| 实际策略 | 在创建容器后读取 HostConfig / Config，记录网络模式、获批域名、用户、资源限制、能力和权限设置。未观察到 Docker 配置时显示“配置待验证”。 |
| 容量保护 | /workspace 默认 96 MiB / 4096 项、/output 默认 50 MiB；执行期间约每 250 ms 扫描，超限停止执行且不提升产物。单文件设置 RLIMIT_FSIZE，默认 20 MiB。原有 /tmp 64 MiB tmpfs、内存、CPU、PID、输出限制继续生效。 |
| 并发 | 一个后端进程内最多 4 个 Docker 执行，跨 Manager 共用限额；手动调试最多 4 个活动记录，2 个工作线程，等待任务显示 queued。 |
| 异常回收 | 容器、代理、网络和目录记录宿主进程 PID 与启动时间。启动运行时或点击恢复时清理已停止所有者的资源；已知当前进程终态且清理失败的任务可重试回收。活跃及无法验证归属的资源保留。 |
| 持久历史 | SQLite 保存最近 100 条记录，终态记录最多 30 天；默认不保存代码和日志。用户勾选后保留脱敏内容。进程异常退出的活动记录恢复为 interrupted，不自动重跑。 |
| 产物保留 | 带可信归属标记的产物和工作区变更载荷保留 7 天，在运行时启动或手动恢复时回收过期目录；过期下载返回 410。 |
| 产物预览与保存 | 仅通过 run + file_id 查询清单中的产物；验证路径、普通文件、大小、SHA-256，拒绝链接和重解析点。文本预览最多 64 KiB，不执行 HTML；下载可保存到本地。 |
| 报告 | 导出 Markdown / JSON，包含状态、阶段、策略、资源、文件、变更、运行环境和可用的脱敏日志。Markdown 使用安全长度的代码围栏。 |
| 环境诊断 | 健康状态定期刷新；显式刷新诊断在隔离容器内执行固定探针，读取真实 Python / 依赖版本。记录镜像 ID、Docker 版本、代码 SHA-256，便于比较环境。 |
| 命令调试 | 手动入口支持 argv JSON 数组和相对 cwd；复用现有 CommandExecutor 和只读权限配置，只允许既有 python / pytest 命令，拒绝 shell 和目录逃逸。 |
| 工作区变更 | 沿用已有变更清单与批准后回写机制；Studio 展示摘要并链接到对应 Agent 运行检查。 |

## 使用

1. 打开 Settings → Sandbox Debug Studio，确认 Docker 已就绪。
2. 选择 Python 或 Command，必要时选择文件系统工作区。
3. 可选择是否保留脱敏代码与日志，点击 Run。
4. Trace 查看实时输出与完整生命周期；Resources 查看测量值；Policy 区分实际容器配置与默认配置。
5. Filesystem 的 Collected Outputs 提供 Preview 和 Download / Save；Trace 提供 Markdown / JSON 导出。
6. Runs 可重新打开历史；保存过的脱敏源代码可以载入编辑器审核后运行。脱敏可能改变代码语义，原始 SHA-256 与脱敏代码不一定相符。

历史数据库位于应用数据目录的 `runtime/sandbox_history.sqlite3`。新增依赖 `psutil` 用于核验本机进程启动时间。

## 实际边界与后续工作

- 总磁盘容量目前是采样式限制，写入可在采样间隔内超出阈值；它不等同于独立卷的硬磁盘配额。硬限额已经覆盖单文件和 /tmp。下一步可评估配额卷或受限临时文件系统。
- 并发预算与运行控制针对单后端进程。多进程、多主机共用 Docker daemon 需要共享调度和所有者身份机制。
- 容器隔离仍依赖 Docker / 宿主内核。更强的不可信代码边界需要评估额外运行时，例如微虚拟机；本次没有声称达到该隔离级别。
- 未携带新归属标记的旧容器和旧目录不会自动删除。已有的非本次容器被保留。
- 手动调试不启用外网、不直接回写宿主目录。网络申请和回写仍通过既有 Agent 权限与审批流程。
- CPU 采样需要相邻测量，极短任务可能没有有效 CPU 数据；未知值不会显示为零。
- 自动回收在运行时初始化时执行，长时间不重启的应用可点击 Recover abandoned resources 触发；尚未增加独立后台周期回收器。
- 历史的脱敏覆盖已知密钥、常见凭据格式及宿主路径，不应被理解为任意内容的全面匿名化。
- 命令历史当前保留 argv，载入后需要重新确认工作区与相对 cwd；尚未提供包含输入快照和依赖的完整可重复执行包。

## 验证

真实 Docker Desktop / Linux 容器回归覆盖标准输出、执行期间日志、断线重连、资源测量、取消与清理、容量超限、命令限制、网络模式记录、孤儿回收、产物校验下载和环境探针；也运行原有隔离、权限、审批、变更冲突和回写回归。报告的 runtime_info 同时记录 Docker HostConfig 的原始 NetworkMode。

前端回归覆盖多次运行不闪烁、旧事件不覆盖新状态、历史活动任务订阅、重连不重复执行、取消等待终态、未知资源显示、命令提交和文本产物预览。生产构建与 PDF 离线资源检查通过。

仅包含本次提交的隔离检出验证：后端 224 项通过、3 项因 Windows 符号链接创建权限跳过；前端 61 项通过，类型检查和生产构建通过。浏览器实测确认执行期间显示 `Hello from AITran Sandbox`，结束后状态及清理阶段完成，Markdown 产物可预览，Resources 显示实测 CPU / 内存 / PID。
