# Chat Markdown 导出与流程状态修复

## 行为

- 已存在 Research 写作项目的 Markdown 导出；本次补齐 Chat 的单条回答及整段会话导出。
- 回答旁增加「导出 Markdown」，会话菜单增加「导出会话 Markdown」，复用现有组件样式。
- 「把上面的回答导出为 Markdown 文档」直接导出已有回答，不调用模型重写正文。
- 「写一份周报并导出为 Markdown 文档」先生成正文，再提供 UTF-8 `.md` 下载。导出内容保留中文、表格及代码块。
- 「不要导出」「如何导出」和资料正文中的指令不会触发自动下载。意图识别仅读取本次用户消息。
- ReAct 直接执行导出；Plan–Execute 先展示固定计划，确认后执行，取消不产生下载。
- 下载文件使用经过清理的文件名，不把模型提供的路径当作服务器写入目标。
- 导出正文按回答消息持久保存，重新打开会话后仍可下载原始正文。

## 后端接口与工具

- `GET /api/conversations/{conversation_id}/export/markdown`：整段会话。
- 增加 `message_id` 查询参数：导出属于该会话的已完成回答；跨会话消息返回 404，未完成回答返回 409。
- `export_markdown_document`：计算型工具，返回文件名、正文及 MIME 类型，由客户端下载，不写入服务器任意路径。
- Agent 返回及流式结束事件增加可选 `markdown_export`，客户端收到后自动下载。
- 会话数据库增加 `conversation_markdown_exports` 表，消息删除时同步清理导出记录。

## 流程状态

- 瞬时检查点立即显示完成，正在执行的工具和任务保留活动状态。
- 使用调用 ID、任务 ID 区分重复调用，更新完成状态时保持原开始顺序。
- 兼容旧事件没有调用 ID 的串行工具调用。
- 运行结束后，不再保留永久旋转状态；缺少完成事件时明确标注未完成，保留失败与取消信息。
- 有异常的终止运行显示 `Completed with issues`。
- 计划确认显示为计划待确认，不误显示为写入工具确认。
- 修复隐藏的非 Chat 路由缓存仍占一屏高度、导致发送后标题被滚动隐藏的问题；缓存组件仍保留以维持本地状态。
