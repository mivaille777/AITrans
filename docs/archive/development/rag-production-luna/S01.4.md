## 改动与合同

- `IndexService` 先创建隔离 generation，再写 Qdrant/BM25；分别核对两库的 chunk ID 多重集与预期完全一致后，才以 manifest 原子发布 READY 指针。失败时把 generation 标记 FAILED、清理两库中的半成品，并保留旧 READY 版本。重导入期间不把旧版本状态改成处理中。
- `IndexManifest.publish_generation()` 原子更新完整文档记录和 active pointer；磁盘保存失败时恢复内存快照。`list_active_generations()` 只返回 READY 文档并验证 generation 指针有效。
- 主 RetrievalService、基准运行时和 Debug Studio 配置变体都按文档 active generation 过滤 dense/BM25/结构检索；manifest 旧记录仍映射到 legacy 数据。Qdrant 以文档 ID 与 generation 成对过滤，BM25 使用同一规则。显式文档范围与 active generation 取交集。
- 扩展只读审计器以比较保留的 READY/RETIRED generations；同一 chunk ID 跨 generation 共存不再误报为差异。FAILED generation 预期已清理；若存储仍留有数据，仍会作为库侧差异出现。
- 保留 `RetrievalService.retrieve()`、`DocumentChunk` 和 API 原合同；新增参数均可选。新增/更新对应内存测试适配器。
