## 改动与合同

- `BM25SparseRetriever` 新增可选 `generation_id` 用于写入、查询、章节查询、邻居扩展、读取、重建和删除。内部 key 按 generation 隔离；`list_chunks()` 默认列出全部版本供审计，`get_chunk()` 和 `search()` 未指定 generation 时仅返回旧式未标记索引。
- `QdrantLocalVectorStore` 新增可选 `generation_id` 用于 upsert、search、get、delete、count 和 list。generation 使用独立 point ID 与 payload 字段；无 generation 的 `search()` 增加“字段为空”过滤，维持旧索引视图且不曝光未发布版本。默认 `list_chunks()` 列出所有 generation。
- 同一 document/chunk ID 可在多个 generation 共存。指定 generation 后操作严格限定该版本；不指定 generation 的文档删除仍清除该文档全部版本，保持整体删除合同。
- 未修改 `IndexService`、`RetrievalService` 或产品 API；当前线上入口没有传 generation ID，新版本尚不参与产品检索。S01.4 才会把 generation 发布与索引服务连接。

## Bad Case、安全与结论

- `same-chunk-id-multiple-generations`：共享 chunk ID 曾会让 BM25 字典/Qdrant point 覆盖前一版本。现在两种存储都按 generation 分区；旧入口仍只查旧式数据，generation-one 与 generation-two 定向查询各返回对应原文。
- `generation-scoped-delete`：删除 generation-one 后，legacy 与 generation-two 数据仍可读取；删除 generation-two 后 legacy 数据仍在。
- generation 元数据不匹配显式参数时拒绝写入；generation 不存在时定向读取返回空。范围约束/引用准确性未运行，因为产品入口尚未接入 generation 参数。
- 当前没有重跑 QASPER 质量/延迟基准：本任务增加存储 API，产品入口未变，存储门禁以隔离的 generation lifecycle 集成测试验证；S00 的指标仍是适用基线。
- Debug Studio Trace 与本任务隔离存储测试无关；未执行桌面 UI 检查。
