## 改动与合同

- `IndexManifestRecord` 新增默认空的 `generation_id`；旧 manifest JSON 缺少该字段时继续读取。
- 新增 `IndexGenerationRecord` 与 `IndexGenerationStatus`：`BUILDING`、`VALIDATING`、`READY`、`RETIRED`、`FAILED`。generation 记录保存 document/generation ID、完整 chunk ID 列表、前一版本、时间和错误。
- 新增 `begin_generation`、`validate_generation`、`publish_generation`、`fail_generation`、`get_generation`、`list_generations` 和 `get_active_generation`。只有 BUILDING 可经 chunk ID 完全一致验证为 VALIDATING，且只有 VALIDATING 可发布；发布在一次 manifest 原子保存中切 active pointer，旧版变成 RETIRED 并保留。
- 新增 generation 重启恢复，并由原有 `recover_interrupted_operations()` 一并调用。未完成的新 generation 标 FAILED；若已有 READY 旧版本，则恢复其为 active/READY。未接入 `IndexService`、Qdrant 或 BM25 写入，外部读写流程仍按旧路径运行。

## Bad Case、安全与结论

- `generation-incomplete-chunk-set`：观测 chunk ID 与预登记 ID 不相等时，返回 `RagInvariantError`，generation 保持 BUILDING，不会切换 active pointer。
- `generation-duplicate-publication`：READY generation 再次发布被拒绝；active pointer 保持不变。
- `generation-interrupted-reimport`：重启时新 BUILDING/VALIDATING 状态变 FAILED；已发布的前一 READY generation 仍是 active，旧 chunk 列表仍保留。
- 本任务没有执行真实文档检索，所以 query scope、引用准确率、Graph Trace 和延迟不适用。索引 stores 还未按 generation 并存，半成品不暴露的端到端门禁留待 S01.3/S01.4。
- 未进行人工 Debug Studio UI 检查；本任务无检索 Trace。
